## Topics covered

1. **Controlled cycles (recap + clarification)** — Looping structures where iteration count is unknown upfront; convergence conditions (stopping rules) determine when loops terminate.

2. **Convergence condition patterns** — Multiple types: loop-until-dry (no new results after K rounds), quality thresholds (score >85), completeness checks (all sections present). Same structure, different stopping criteria.

3. **Loop vs graph engineering distinction** — Single-agent looping (generator → reviewer → score) is loop engineering; controlled cycles embedded in larger agent graphs is graph engineering.

4. **Terminology provenance** — "Controlled cycle" is newer graph-engineering framing; "convergence condition" borrowed from optimization/neural nets. Document synthesizes sources (Twitter practitioners, Anthropic, Machina course); vocabulary not yet standardized.

5. **Pipeline vs parallel topology** — Parallel enforces barrier (all items wait at checkpoint before next stage); pipeline allows items to flow independently through sequential stages. Relay race vs lockstep execution.

6. **Pipeline as linear graph** — Multiple stages as nodes, items flow through asynchronously. Contrasted with diamond pattern (fan-out, merge, reduce).

7. **VoiceTutor feature: topic repetition tracking** — Count how many times concepts resurface; signal for reinforcement needs or comprehension difficulty. Surface in session recap.

8. **VoiceTutor feature: mid-session tool calling** — Ability to call tools (e.g., read wiki) to take targeted notes on specific sections mid-conversation.

9. **VoiceTutor feature: conversation checkpoints** — Pause triggered by time or coverage thresholds to check in, verify understanding, allow redirection.
